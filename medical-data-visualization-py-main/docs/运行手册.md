# 运行手册

> 本文档汇总本项目的环境要求、启动步骤与常见问题排查，方便换机器 / 答辩演示时快速复现。

---

## 1. 环境要求

| 组件 | 版本要求 | 说明 |
|---|---|---|
| **Python** | **3.10.x**（推荐 3.10.11） | `torch==2.1.2`、`pandas==1.4.3`、`matplotlib==3.5.2` 只到 3.10/3.11 有预编译轮子 |
| **Node.js** | 14+（推荐 **18 LTS**） | 实测环境：**Node v24.16.0 + npm 11.13.0**，可正常运行；需 `--openssl-legacy-provider`，首次编译约 1~2 分钟 |
| **MySQL** | 8.0+ | 排序规则用到 `utf8mb4_0900_ai_ci`，5.7 会失败 |
| **Git** | 任意 | 需要 `git lfs` 时才要 LFS 扩展（本项目权重已改为 Release 分发，非必需） |

## 2. 首次安装

### 2.1 创建 Python 虚拟环境

```powershell
# 在项目根目录（与 app.py 同级）
& "C:\Users\<你>\AppData\Local\Programs\Python\Python310\python.exe" -m venv venv
.\venv\Scripts\Activate.ps1
```

> ⚠️ venv 是**绑定解释器绝对路径**的。如果以后卸载/移动了 Python 3.10，venv 会直接失效（报 `No Python at ...`），只能删掉重建。

### 2.2 安装依赖

```powershell
pip install -r requirements.txt
```

**已知问题与处理**：

| 包 | 问题 | 处理 |
|---|---|---|
| `mysqlclient==2.2.0` | Windows 无预编译轮子，需要 MSVC 编译 | 跳过即可，项目实际用 `PyMySQL` |
| `openai==1.3.0` + 新版 `httpx` | 报 `TypeError: Client.__init__() got an unexpected keyword argument 'proxies'` | `pip install "httpx==0.24.1"` |
| `wordcloud==1.8.2.2` + Pillow 10+ | `ImageDraw has no attribute 'textsize'` | 项目未使用该库，可忽略 |
| `imbalanced-learn` 新版 | 会把 `scipy` / `scikit-learn` 升级到更高版本 | 功能不受影响，可接受 |

国内建议配镜像加速：

```powershell
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 2.3 配置 `.env`

复制模板并填入真实值：

```powershell
copy .env.example .env
```

必须配置的项：

| 变量 | 说明 |
|---|---|
| `DB_PASSWORD` | **必填**，真实 MySQL 密码（不填会抛 `DB_PASSWORD is not set`） |
| `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_NAME` | 默认 `127.0.0.1:3306` / `root` / `medicalinfo` |
| `DEEPSEEK_API_KEY` | 不填则 AI 助手返回占位文案（`https://platform.deepseek.com/` 申请） |
| `FLASK_SECRET_KEY` | 建议填随机串 |

> `.env` 已被 `.gitignore` 排除，**不会进版本库**。

### 2.4 获取模型权重（必做，约 780 MB）

```powershell
python download_weights.py
```

或手动从 Release 下载：

| 文件 | 放置路径 |
|---|---|
| `medical_model.pth` | `machine/medical_model.pth` |
| `pytorch_model.bin` | `machine/bert-base-chinese/pytorch_model.bin` |

下载页：https://github.com/jully-91/medical-data-visualization/releases/tag/v1.0-weights

> 缺少权重时：大屏、数据管理、报告生成均正常，仅「数据预测」提示「模型尚未加载」。

### 2.5 初始化数据库

```powershell
python -m spiders.import_database
```

脚本会自动 `CREATE DATABASE medicalinfo`、建表并导入 `medicalinfo.sql`（含 344 条示例病例）。

预期输出：

```

✓ cases表创建成功
✓ 表中共有 344 条记录
```

### 2.6 安装前端依赖

```powershell
cd front-end-template-1-master

```

## 3. 启动

### 方式一：双击脚本启动（推荐）

| 脚本 | 作用 |
|---|---|
| **`start-all.bat`** | 一次启动全部 3 个服务（各开一个独立窗口） |
| `start-backend.bat` | 只启动 Flask 主服务（5000） |
| `start-websocket.bat` | 只启动 SocketIO AI 助手（5001） |
| `front-end-template-1-master\start-dev.bat` | 只启动前端（8080） |

脚本已内置：切换到正确目录（`cd /d "%~dp0"`）、UTF-8 编码（`chcp 65001`）、
前端所需的 `NODE_OPTIONS=--openssl-legacy-provider`，
并在缺少 venv / `.env` / 模型权重时给出明确提示（`start-all.bat` 还会自动调用权重下载）。

### 方式二：手动开三个终端

**所有命令都在项目根目录（与 `app.py` 同级）执行**。

```powershell
# 终端 1：Flask 主服务（REST API / 数据 / 报告）→ 5000
.\venv\Scripts\python.exe app.py

# 终端 2：WebSocket / AI 医疗助手 → 5001
.\venv\Scripts\python.exe websocket_chat.py

# 终端 3：前端开发服务器 → 8080
cd front-end-template-1-master
$env:NODE_OPTIONS="--openssl-legacy-provider"   # Node 17+ 需要
npm run serve
```

> 前端目录下已提供 **`start-dev.bat`**，双击即可启动（已内置 `chcp 65001` /
> `NODE_OPTIONS` / 失败时暂停显示报错），不用手动记环境变量。

> **启动顺序**：先 5000，再 8080（前端 `/api` 代理指向 5000）。
> **后端首次启动约 1~2 分钟**：要加载 390 MB 模型并为 344 条病例计算特征向量。

启动成功的标志（终端 1）：


### 停止服务

**方式一启动的**：直接关闭对应标题的窗口（`Flask-5000` / `SocketIO-5001` / `Vue-8080`）；
或在窗口内按 `Ctrl+C`，出现“终止批处理操作吗(Y/N)?”时按 `Y`。

**方式二启动的**：在对应终端按 `Ctrl+C`。

**按端口强制停止**（窗口找不到 / 端口被占用 / 进程卡死时最可靠）：

```powershell
# 停掉单个服务（示例：Flask 5000）
Get-NetTCPConnection -LocalPort 5000 -State Listen -ErrorAction SilentlyContinue |
    Select-Object -ExpandProperty OwningProcess -Unique |
    ForEach-Object { Stop-Process -Id $_ -Force }

# 一次停掉三个服务
5000,5001,8080 | ForEach-Object {
    Get-NetTCPConnection -LocalPort $_ -State Listen -ErrorAction SilentlyContinue |
        Select-Object -ExpandProperty OwningProcess -Unique |
        ForEach-Object { Stop-Process -Id $_ -Force -ErrorAction SilentlyContinue }
}
```

确认已停止（**无输出**即端口全部释放）：

```powershell
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 5000,5001,8080 }
```

> ⚠️ **不要**图省事执行 `Get-Process -Name python,node | Stop-Process -Force`，
> 这会连其他项目的 Python / Node 进程一起杀掉。优先按端口精确定位。

> 💡 **重要**：`websocket_chat.py` 开启了 Flask debug 模式（reloader），实际存在**三层进程**：
> `终端` → `venv\Scripts\python.exe`(启动器) → `Python310\python.exe`(真正跑服务)。
> 按端口杀通常只命中一层，**残留的父/子进程会立刻重新占用端口**。
> 所以杀完**务必复查端口**；若仍被占用，用下面的命令定向清理：
>
> ```powershell
> Get-CimInstance Win32_Process -Filter "Name='python.exe'" |
>     Where-Object { $_.CommandLine -match 'websocket_chat|app\.py' } |
>     ForEach-Object { Stop-Process -Id $_.ProcessId -Force }
> ```
>
> `start-all.bat` 启动时也是同理：直接**关窗口**最干净，比按端口杀更可靠。

## 5. 常见问题

### 5.1 预测结果恒为「特征不明显 / 未知」，置信度约 42%

**症状**：无论输入什么症状，都返回 `特征不明显 / 未知`，置信度在 41%~43% 之间几乎不变。

**根因**：`machine/tree.py` 的 `load_model()` 里有 `print("✅ 模型权重加载成功！")`。
在中文 Windows 的 **GBK 控制台**下 `✅` 无法编码 → 抛 `UnicodeEncodeError` →
被 `app.py` 的 `except` 捕获 → `except` 内的 `print("❌ ...")` 又崩一次 →
进程带着**未完成初始化的模型**继续跑（分类头还是随机权重）。

**解决**：本项目已在 `app.py` / `websocket_chat.py` / `machine/tree.py` 顶部统一加了：

```python
sys.stdout.reconfigure(encoding="utf-8", errors="replace")
```

若你改动了这部分代码，请保留它。

**另外一个隐藏坑**：用 PowerShell 的 `Invoke-RestMethod -Body $json` 测接口，
默认按 ASCII 发送，中文会变成 `?`，也会得到恒定的 42%。
**测试中文接口请用 Python `requests` 的 `json=` 参数**或 `curl.exe`。

### 5.2 `app.py` 启动直接报 `UnicodeEncodeError`

同 5.1，检查三个入口文件顶部的 `reconfigure` 是否还在。

### 5.3 训练 / 推理特别慢

PyTorch 默认可能只用 1 个线程。多核机器上显式设置：

```python
import torch
torch.set_num_threads(14)     # 或设置环境变量 OMP_NUM_THREADS=14
```

参考：28 核机器上 344 条数据训练 10 epoch ≈ **571 秒**；单线程会慢 10 倍以上。

### 5.4 `npm run serve` 报 `ERR_OSSL_EVP_UNSUPPORTED` 或停在 `Starting development server...`

**现象**：

```
Error: error:0308010C:digital envelope routines::unsupported
```

或进程卡在 `INFO Starting development server...` 很久不动。

**解决**：

```powershell
$env:NODE_OPTIONS="--openssl-legacy-provider"
npm run serve
```

> 用 `start-dev.bat` 双击启动则无需手动设置（脚本已内置）。

**原因（重要）**：

1. `vue-cli 4.5` 使用的是 **webpack 4**，它内部用 **MD4** 算法为模块计算哈希；
2. Node 17 起内置 **OpenSSL 3.0**，MD4 属于"已不安全的老算法"，被移入
   **legacy provider** 且**默认不加载**；
3. 于是 webpack 4 调用 `crypto.createHash('md4')` 直接抛 `0308010C` 错误。

`--openssl-legacy-provider` 的作用就是让 OpenSSL **额外加载 legacy 算法库**，
从而恢复 MD4 可用。可自行验证：

```powershell
# 不设变量 → 报错
node -e "require('crypto').createHash('md4')"

# 设置后 → 正常返回哈希
$env:NODE_OPTIONS="--openssl-legacy-provider"
node -e "require('crypto').createHash('md4')"
```

**其他说明**：

- 该环境变量**仅对当前终端会话生效**，关闭终端即失效；对本机其他 Node 项目无影响。
- 首次编译需要 1~2 分钟，**不要中途 Ctrl+C**（会破坏缓存导致更慢）；
  第二次起通常会降到 10~30 秒。
- 若长期使用，建议装 Node 18 LTS 会更流畅（本项目实测 Node 24 亦可正常运行）。
- ⚠️ 网上常见的「改 `vue.config.js` 的 `output.hashFunction = 'sha256'`」方案
  **不一定可靠**：`mini-css-extract-plugin`、`terser-webpack-plugin` 等插件会各自
  调用 `createHash('md4')`，不受该配置控制。**本项目未采用此方案**，请保持使用环境变量。

### 5.5 端口被占用 / 同一个服务起了多份

Windows 的 `SO_REUSEADDR` 允许多个进程绑定同一端口，`kill` 终端可能留下孤儿进程。

```powershell
# 查看端口占用
Get-NetTCPConnection -State Listen | Where-Object { $_.LocalPort -in 5000,5001,8080 }

# 清理全部 python 进程后重启
Get-Process -Name python | Stop-Process -Force
```

### 5.6 数据库连接失败

- 确认 MySQL 服务已启动：`Get-Service | Where-Object Name -match mysql`
- 确认 `.env` 的 `DB_PASSWORD` 是真实密码（不是 `your-db-password-here`）
- 确认库已初始化：`python -m spiders.import_database`

### 5.7 AI 助手返回占位文案 / 无响应

- 检查 `.env` 的 `DEEPSEEK_API_KEY` 是否为真实 Key
- **修改 `.env` 后必须重启 `websocket_chat.py`**（只在启动时读取一次）

## 6. 维护操作

### 6.1 重新训练模型

```powershell
python -m machine.tree
```

会重新生成 `machine/medical_model.pth` 与 `machine/classes.npy`（依赖 2.5 的数据库数据）。

### 6.2 重置数据库

```powershell
python -m spiders.import_database
```

> 注意：该脚本是追加导入，不会先清空 `cases` 表。需要干净重置时先手动
> `DROP DATABASE medicalinfo;` 再执行。

### 6.3 重新下载权重

```powershell
python download_weights.py
```

已存在且大小正确的文件会自动跳过；支持断点续传（`.part` 文件）。
