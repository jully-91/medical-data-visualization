# 阶段四 · 项目部署与测试 操作手册

> 对应实训任务：**阶段四：项目部署与测试 → 任务1：项目测试、整合、发布（选做）**
> 本项目：Flask + Vue，跑在 **Linux 沙箱**（有 root、可联网、MySQL 已有 `medicalinfo` 数据），**平台执行一条命令**。

---

## 0. 一句话用法

```bash
bash run.sh
```

它会把「自检 → 装依赖 → 构建前端 → 启动服务 → 冒烟测试 → 生成报告」全做完，
最后打印一行 `RESULT {...}`，退出码 0 表示成功。

需要平台常驻（命令不能退出）时：

```bash
bash run.sh serve
```

---

## 1. 能脚本化的边界

| 工作 | 是否自动 | 说明 |
| --- | --- | --- |
| 数据库连通性探测 | 自动 | 依次尝试 `DB_PASSWORD` 环境变量、`.env`、空密码等，连上就把可用凭据写回 `.env` |
| Python 依赖安装 | 自动 | 缺才装；已剔除 `mysqlclient`（Linux 上编译易失败，本项目实际用 PyMySQL） |
| 前端 `npm run build` | 自动 | 无 `node_modules` 时先 `npm install`（npmmirror 源） |
| 启停服务 | 自动 | 后台启动，pid 记录 + ss/lsof/fuser 三重兜底清理端口 |
| 冒烟测试 + 测试报告 | 自动 | 14 条用例，写 `docs/阶段四-测试报告.md` + `.json` |
| 装 Python/Node/MySQL 本体 | 手工 | 镜像里通常已预装 |
| 模型权重（约 800MB） | 手工 | 缺失只影响「在线预测」页，其余功能正常 |
| 防火墙/安全组 | 手工 | 沙箱内一般不需要 |

## 2. 一条命令的流水线

| 步骤 | 内容 | 失败退出码 |
| --- | --- | --- |
| 1 | 数据库自检：探测 MySQL、确认 `cases` 表有数据、必要时生成 `.env` | 1 |
| 2 | Python 依赖：缺则 `pip install`（清华/阿里源自动切换，torch 缺则走 CPU 源） | 2 |
| 3 | 前端构建：`npm run build` → `front-end-template-1-master/dist` | 3 |
| 4 | 启动：后端 5000（waitress，缺则 flask）、前端 8080，等待端口就绪 | 4 |
| 5 | 冒烟测试：14 条用例，生成报告 | 5 |

依赖装好、`dist` 已存在时，重复执行会跳过对应步骤（幂等）。

## 4. 常用命令

```bash
bash run.sh                  # 全流程（默认）
bash run.sh check            # 只自检，不动任何东西
bash run.sh --skip-install   # 依赖已预装，跳过 pip
bash run.sh --skip-build     # dist 已构建，跳过 npm
bash run.sh --rebuild        # 强制重新构建前端
bash run.sh --with-chat      # 连 AI 助手(5001) 一起起
bash run.sh test             # 服务已在跑，只做测试
bash run.sh status           # 看三个端口/产物状态
bash run.sh stop             # 停服务
bash run.sh pack             # 打包发布物 → release/medicine-release-*.zip
```

也可以直接调 Python（`run.sh` 只是入口壳，会自动挑 venv 或 python3）：

```bash
python3 deploy/deploy.py all
python3 deploy/deploy.py check
```

## 5. 运行结构

| 服务 | 端口 | 进程 | 说明 |
| --- | --- | --- | --- |
| 后端 API | 5000 | `app.py` + waitress | 大屏数据、数据管理、报告、导出、AI、预测 |
| 前端 | 8080 | `deploy/serve_dist.py` | 托管 `dist`；支持 history 路由回退；`/api` 反代到 5000 |
| AI 助手 | 5001 | `websocket_chat.py` | 可选（`--with-chat`） |

为什么前端要一个自定义静态服务器：

- Vue Router 是 **history 模式**，`python -m http.server` 直接访问 `/pred` 会 404，`serve_dist.py` 会回退到 `index.html`；
- 前端 `axios.baseURL` 用相对路径 `/api`，由它反代到后端，**换 IP 不用重新 build**。

后端没装 `waitress` 时自动退回 flask 内置服务器（能跑，但不是生产级），建议：
`pip install waitress`（脚本不会强制装）。

## 6. 与教材（Django + Tomcat）的对应

| 教材 | 本项目 | 脚本动作 |
| --- | --- | --- |
| 上传 `medicine.zip` 解压 | 上传发布包解压 | `run.sh pack` 生成 |
| 装 Python 3.9、编译安装 | 用镜像自带 Python 3.8+ | 自动检测 |
| `pip install -r requirements.txt` | 同（剔除 mysqlclient） | 自动 |
| 配 sqlite3 / pysqlite3 | 不需要（用 MySQL） | — |
| `npm run build` | 同 | 自动 |
| dist 拷进 `webapps/ROOT`、启 Tomcat | `serve_dist.py` 托管 dist | 自动 |
| `nohup java -jar ... &` | waitress/flask 后台进程 | 自动 |
| `ALLOWED_HOSTS = ["*"]` | 监听 `0.0.0.0` | 自动 |
| 人工点页面验收 | 14 条冒烟用例 | 自动 |

那套是 Hadoop/Kylin/Tomcat 大数据环境用的，和这个 Flask 项目无关。

## 7. 手动部署（不想用脚本时）

```bash
# 1) 依赖
python3 -m pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
#    若 mysqlclient 编译失败：从 requirements.txt 删掉它（项目实际用 PyMySQL）

# 2) 数据库：确保 .env 里 DB_HOST/DB_USER/DB_PASSWORD/DB_NAME 正确
#    数据已导入时跳过；否则： mysql -uroot -p medicalinfo < medicalinfo.sql

# 3) 前端
cd front-end-template-1-master
npm install --registry=https://registry.npmmirror.com
NODE_OPTIONS=--openssl-legacy-provider npm run build     # Node 17+ 必须
cd ..

# 4) 启动
nohup python3 app.py > backend.log 2>&1 &                # 需自行改成 host=0.0.0.0
nohup python3 deploy/serve_dist.py --port 8080 --api http://127.0.0.1:5000 > frontend.log 2>&1 &

# 5) 访问与测试
python3 deploy/smoke_test.py --api http://127.0.0.1:5000 --web http://127.0.0.1:8080
```

## 8. 常见问题

**Q1 `vi /etc/profile` 报 `E45: 'readonly' option is set`**
文件只读。先判因：`id -u`（不是 0 就 `sudo`）、`ls -l /etc/profile`、`findmnt -no OPTIONS /`（有 `ro` 就是只读挂载）、`touch /etc/profile`。
只读挂载时改不了 `/etc/profile`，把 export 写进 `~/.bashrc` 再 `source ~/.bashrc`；只是 vi 标志则 `:set noreadonly` 后 `:w`。
本项目阶段四**不需要**改它。

**Q2 退出码 1：数据库连不上**
`mysql -uroot -p -e "select count(*) from medicalinfo.cases"` 先确认库在、表有数据；
再确认 `.env` 或环境变量 `DB_HOST/DB_USER/DB_PASSWORD/DB_NAME`。

**Q3 退出码 2：依赖装不上**
多为网络或编译问题。看是不是卡在 `mysqlclient`（脚本已剔除）；手动执行脚本打印的那条 `pip install` 命令定位；
torch 太大可先装 CPU 版：`pip install torch --index-url https://download.pytorch.org/whl/cpu`。

**Q4 退出码 3：前端构建失败**
- Node 版本过低：需 16/18+；`node -v` 看版本；
- `error:0308010C:digital envelope routines::unsupported`：Node 17+ 需要 `NODE_OPTIONS=--openssl-legacy-provider`（脚本已自动加）；
- 内存不足：`export NODE_OPTIONS="--max-old-space-size=4096"`；
- `node_modules` 损坏：`rm -rf node_modules package-lock.json && bash run.sh`。

**Q5 退出码 4：端口起不来**
看 `deploy/logs/backend.log` 末尾（脚本会自打印）。常见：模型加载慢（首次 1~2 分钟，脚本等 420 秒）、
MySQL 中途断开、依赖缺失。端口占用会被脚本自动清理，清理失败会提示 pid。

**Q6 退出码 5：有用例失败**
打开 `docs/阶段四-测试报告.md` 第四节，报告已按用例给出「可能原因 + 处理建议」。
常见：`/getHomeData` 返回空（库表没数据）、`/pred` 404（没用 `serve_dist.py`）、`/api` 502（后端没起）。

**Q7 平台执行完命令后访问不了**
平台可能在命令结束后回收进程组。改用 `bash run.sh serve`（前台常驻）；
或确认平台允许后台进程存活。

**Q8 「在线预测」提示模型未加载**
`machine/medical_model.pth` 不在。放到 `machine/` 下即可，不影响其他页面与测试（对应用例记为「跳过」而非失败）。
